# Календарь сюжета

Расширение SillyTavern: красивый календарь времени и событий РП с отдельной моделью-календаристом и короткой памятью для модели, которая пишет историю.

## Установка

В SillyTavern открой **Расширения → Установить расширение** и вставь ссылку:

```text
https://github.com/Nufahi/ST-Calendar
```

Обнови страницу после установки.

### Вручную

Скопируй папку `ST-Calendar` в:

```text
SillyTavern/public/scripts/extensions/third-party/ST-Calendar/
```

Внутри должны лежать `manifest.json`, `index.js`, `core.js`, `prompts.js`, `ui.js` и `style.css`. Папки `node_modules` и `tests` для работы расширения не нужны. Обнови страницу Tavern.

Нужна актуальная SillyTavern с `SillyTavern.getContext()` и встроенным **Connection Manager** с поддержкой `ConnectionManagerRequestService`. Анализ использует сохранённый профиль Chat Completion или Text Completion. Сборки или серверной части у расширения нет.

## Первый запуск

1. Открой чат и выбери **Календарь** в волшебной палочке. Также есть кнопка в настройках расширений и команда `/calendar`.
2. Во вкладке **Настройки** выбери профиль подключения модели-календариста. Если конкретный профиль не выбран, используется активный сохранённый профиль Connection Manager. Если его нет, сохрани/выбери профиль в API Connections. Отдельный запрос не переключает модель твоего РП.
3. Нажми **Создать календарь года**. Модель определит дату, страну/регион, эру и сеттинг; составит фоновые события для всех 12 месяцев.
4. Проверь получившуюся дату. Кнопка карандаша возле текущей даты позволяет поправить её, страну и сеттинг вручную. Под календарём показывается основание, по которому модель выбрала дату.

В **Расширения → Календарь** находится сворачиваемая карточка в стиле LiteBranch: включение календаря, выбор расположения кнопки и вида окна. Здесь выбираются независимо:

- **Кнопка:** в волшебной палочке, плавающая или обе.
- **Окно:** модальное всплывающее либо плавающее рядом с чатом, чтобы продолжать писать.

Кнопка **Модель и память** сразу открывает настройки анализатора. Чекбоксы расположены рядом с подписью: переключается вся строка. Настройки сохраняются сразу.

Режим уже открытого окна меняется сразу. Плавающее окно использует Popover API, чтобы корректно располагаться поверх мобильного интерфейса Tavern и оставлять чат доступным. В старом браузере без этого API открывается модальное окно.

В **0.1.4** исправлены исчезновение плавающего окна на телефоне и зависание при возврате к всплывающему режиму. Проверено переключение в обе стороны и повторное открытие скрытого окна в Chromium с воспроизведёнными мобильными стилями Tavern.

На телефоне окно подстраивается под высоту экрана, содержимое прокручивается отдельно от шапки. Кнопки действий под пометкой не сжимают её текст. Годовая сетка показывает два месяца в ряд, на самых узких экранах — один; сенсорные кнопки увеличены.

## Как работает календарь

Модель получает карточку персонажа (в группе — участников), описание, personality, scenario, персону пользователя, недавние сообщения и включённые записи книг лора, привязанных к чату/персонажам. Для длинных карточек, сообщений и лора действуют ограничения длины. Это отдельный запрос анализатора, а не полный промпт основного РП; глобальные книги и механизм активации World Info не воспроизводятся.

Если точной даты нет, модель предлагает согласованную гипотезу. Реальная сегодняшняя дата не подставляется. Для вымышленных миров можно указать свою эру и регион; сетка пока использует **12 григорианских месяцев, годы 0001–9999**.

### Точки и пометки

- **Праздник** — календарный праздник, фестиваль, памятный день.
- **Событие мира** — сезонное или общественное событие, фон для истории.
- **Сюжет** — действительно произошедшее важное изменение.

Нажми день: под сеткой появятся краткие пометки. Кнопка **Весь год** показывает все месяцы. События можно добавлять, редактировать и удалять вручную. Важный сюжетный факт можно закрепить для приоритетного включения в память.

Годовой план содержит до 4 событий на месяц (обычно 1–2). Планы не считаются случившимися фактами и не предрешают действия героев. При переходе на другой год нажми **Придумать события … года**. Обновление уже созданного года заменяет только его автоматически придуманные праздники и события мира.

### Автоматические проверки

По умолчанию анализ запускается после **2 новых сообщений**, когда персонаж закончил ответ: обычно это пост пользователя + пост персонажа. Интервал настраивается. Первое создание календаря принимает существующую переписку за исходную точку; автоматические сюжетные пометки появляются по новым сообщениям.

Анализатор получает строгую инструкцию записывать только важное: союз, обещание с последствиями, потерю, перелом отношений, раскрытую тайну, завершение цели. Максимум 3 коротких пометки за проверку. Обычные разговоры и бытовые действия должны давать пустой список. Название — до 60 символов, пояснение — до 120. Отбор значимости делает модель; промпт можно настроить.

Дата сдвигается только по признакам прошедшего времени в сюжете, а не по числу сообщений. Длинная непроверенная история разбирается последовательными пакетами. **Проверить сюжет** запускает следующий пакет вручную.

При свайпе, редактировании или удалении исходных сообщений зависимые автоматические пометки и изменения даты откатываются. Ручные и отредактированные вручную записи сохраняются. Ответ анализатора отбрасывается, если во время запроса сменился чат, изменились исходные сообщения или пользователь поправил календарь.

После ошибки автоматическая проверка приостанавливается до ручного запуска, изменения настроек или смены чата. Некорректный/неполный JSON не перезаписывает календарь. Для годового ответа рекомендуется лимит 8192–16384 токенов, особенно у думающих моделей. Отмена прерывает только запрос анализатора через его собственный AbortSignal.

Стандартные промпты написаны на английском. Модель получает инструкцию писать названия, пометки, страну, сеттинг и пояснения **на языке текущего РП**, определяя его по последним сценам, а не по языку карточки или внутренних промптов. JSON-ключи остаются английскими. Если ты сохранял собственный промпт, он имеет приоритет; кнопка **Вернуть стандартный промпт** включает новую версию.

## Память для РП

По умолчанию краткая память автоматически добавляется системной вставкой в контекст основного чата. В ней только:

- текущая дата и место;
- последние важные факты (закреплённые — первыми);
- ближайшие праздники/события, явно помеченные как **план мира, ещё не факт**.

Ограничения по умолчанию: **2200 символов**, до **10 сюжетных фактов**, события мира на **14 дней вперёд**. Весь год в каждый РП-запрос не отправляется. Во вкладке **Память** доступен точный предпросмотр блока.

Можно выбрать **Только через мои макросы** и вставить в промпт или заметку автора:

```text
{{rp_calendar}}
```

Дополнительные макросы:

| Макрос | Значение |
| --- | --- |
| `{{rp_calendar}}` | Весь короткий блок календарной памяти |
| `{{rp_date}}` | Текущая дата, место и эра |
| `{{rp_events}}` | Отобранные факты и ближайшие планы |

Не используй полный макрос вместе с автоматической вставкой, если не нужно дублирование. В режиме **Не отправлять** автоматическая вставка и макросы пустые. Поддерживаются обычный и экспериментальный движки макросов Tavern; после переключения движка обнови страницу.

### Совместимость с пресетами и расширениями

- Calendar пишет только в собственные ключи `ST-Calendar` настроек, метаданных и extension prompt. Текст сообщений и порядок промптов пресета не переписываются.
- Макросы возвращают текст; они не вызывают генерацию и не меняют переменные `setvar`. Фигурные скобки макросов внутри пометок обезвреживаются перед вставкой.
- Для ручного размещения выбери **Только через мои макросы** и добавь `{{rp_calendar}}` отдельным включённым блоком Prompt Manager рядом с историей. В автоматическом режиме ничего добавлять в пресет не нужно.
- Память помечена как справочные данные: текущая сцена приоритетнее устаревшей пометки, стиль, язык, формат и свобода действий персонажей сохраняются. Планы мира не объявляются свершившимися фактами.
- С версии 0.1.2 анализ всегда идёт через Connection Manager. Запасной `generateRaw` убран: он использовал общие события генерации и временный глобальный лимит ответа. Пресет профиля даёт параметры API, а не набор RP-инструкций из Prompt Manager.
- В экспериментальном реестре уже занятые имена макросов сохраняются за владельцем; при выгрузке удаляются только собственные определения. В старых сборках Tavern публичного API проверки владельца legacy-макроса может не быть.

Проверены 13 локальных JSON-пресетов из `preset/`, включая «Несквик» и подпапку `гпт`: имена трёх макросов Calendar не заняты, блок истории включён. Полная совместимость произвольных сторонних расширений требует проверки в запущенной Tavern; независимые расширения по-прежнему могут одновременно отправлять свои API-запросы.

## Хранение

Дата, сеттинг, события и состояние проверок хранятся в метаданных **конкретного чата**. Настройки интерфейса, профиль подключения, интервалы и промпты общие. Доступны экспорт/импорт JSON и удаление календаря текущего чата. Импорт переносит факты, но не привязывает их к индексам сообщений другого чата.

## Разработка и проверки

```sh
npm ci
npm test
```

Тесты используют Node.js 20.19+ и Happy DOM: даты/високосные годы, полный годовой JSON, краткая память, откат свайпов/удалений, безопасный текстовый рендеринг, работа с профилем, изоляция чатов и устаревшие ответы. Для работы в Tavern npm-зависимости не нужны.

Для версии 0.1.1 интерфейс дополнительно проверен в Chromium на изолированной странице: ширины 320, 390, 768 и 1280 px, низкое горизонтальное окно и удвоенный шрифт. Проверены выход элементов за границы, прокрутка, клики по подписям чекбоксов, расположение кнопок, оба режима окна и клавиатура. Проверка внутри живой Tavern с пользовательскими темами отдельно не проводилась.
